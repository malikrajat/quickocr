Log Lens privacy policy

Version 1.1.0 · effective 7 November 2026

Log Lens is a local-first diagnostics tool. It stores redacted error logs in your browser, has no analytics, and never sends log data anywhere unless you explicitly enable auto-send to an HTTPS endpoint you choose.

What Log Lens stores

  • Captured log entries: timestamp, level, source, message, optional stack trace, small context fields, sanitized page URL and (for page capture) the tab id.
  • Your settings: capture levels, retention limits, auto-open mode, notification and badge preferences, an optional email recipient, auto-send configuration and public-API approvals.
  • Small operational state: last error time, last notification/open time, last send status and queued send batches.

Everything is stored in chrome.storage.local, subject to the ring-buffer retention and size limits you configure. Clearing logs deletes the entries and queued send batches.

What Log Lens never captures

Cookies or session stores Never read or stored.
Form data, passwords or keystrokes Never read or stored.
Request headers or bodies Never read or stored, including authorization headers.
Response bodies Never read or stored.
Page content or DOM text Never read. Page-error capture records only the error message, stack, filename, line and column.
Browsing history Not requested or accessed.

Redaction

Before an entry is stored, exported, emailed or sent, Log Lens redacts:

  • Bearer, Basic and Token authorization values
  • Cookies and session identifiers
  • Passwords, passphrases and client secrets
  • API keys and common provider token formats (OpenAI, GitHub, Slack, AWS, Google, JWTs)
  • Private-key blocks, URL credentials and sensitive query/header values

URLs are reduced to origin and path: query strings, fragments, usernames and passwords are removed.

Page capture is opt-in

Extension errors and unhandled rejections in Log Lens itself are captured by default. Page errors and network failures require an explicit toggle and Chrome host permission. A MAIN-world instrumentation script patches fetch and XMLHttpRequest only to record the method, sanitized URL, status and duration; an isolated bridge forwards those events to the service worker. It does not inspect headers, bodies, DOM content or form values.

Auto-send is opt-in

Auto-send is disabled by default and requires a consent checkbox, an HTTPS endpoint and Chrome host permission for that endpoint. When enabled, redacted JSON (loglens/v1) is POSTed to the endpoint you configure. Requests omit credentials, use referrerPolicy: no-referrer, include no auth headers and never read the response body. You can disable auto-send and clear queued batches at any time.

Public API

Other extensions can submit logs through chrome.runtime.onMessageExternal only if you approve their extension id or enable "allow all installed extensions". Web origins must be explicitly approved. Submissions are rate-limited to 60 per minute per sender and pass through the same redaction pipeline.

Email, export and screenshots

Email logs opens a mailto: link in your mail application; Log Lens does not send email. Exports and screenshots are generated locally and downloaded through Chrome's normal download flow. Panel screenshots use a local DOM-to-image conversion; page screenshots use chrome.tabs.captureVisibleTab after you click the button and, if needed, grant site access.

No analytics or remote code

There are no analytics, telemetry, ads, trackers or third-party scripts. The extension contains no remote code and its content security policy allows scripts only from the extension package. Log Lens can be verified from its source, tests and packaged ZIP.

Retention and deletion

Entries older than your retention window are pruned automatically, and the oldest entries are removed when the configured maximum or the storage byte budget is reached. "Clear logs" removes all entries and pending send batches. Uninstalling the extension removes its local storage according to Chrome's normal behaviour.
